## 무엇을 실습했나요?

2026년 10월, 수업에서 제공한 Vue와 Vite 기반 영화 검색 예제를 두 가지 방식으로 배포했습니다. 예제를 실행하고 배포 설정을 수정하는 개인 실습이었으며, 영화 검색 기능을 처음부터 직접 구현한 것은 아닙니다.

첫 번째는 컴퓨터에서 빌드한 결과물을 직접 올리는 방식이고, 두 번째는 GitHub Actions가 소스 코드를 빌드하고 배포하는 방식입니다.

## 두 배포 방식의 차이

| 구분 | 빌드 결과물 직접 업로드 | GitHub Actions 자동 배포 |
| --- | --- | --- |
| 실습 저장소 | movie-lab | movie-lab-actions |
| 빌드하는 곳 | 내 컴퓨터 | GitHub Actions 실행 환경 |
| GitHub에 올리는 내용 | 컴퓨터에서 만든 빌드 결과물 | 소스 코드와 배포 설정 |
| 수정 후 반영 과정 | 다시 빌드한 결과물을 올림 | 소스를 푸시하고 자동 빌드·배포 결과를 확인함 |

첫 번째 실습에서는 제공된 예제를 실행하고 빌드 결과를 확인한 뒤 결과물을 저장소에 올렸습니다.

두 번째 실습에서는 저장소 이름에 맞게 Vite의 `base` 경로를 수정하고 GitHub Actions를 이용한 자동 빌드와 배포를 설정했습니다.

두 방식 모두 공개 사이트를 만들지만, 빌드를 실행하는 위치와 수정 후 결과를 반영하는 과정이 다릅니다.

## Vite의 base 경로는 왜 맞춰야 하나요?

두 실습의 배포 주소에는 각각 `/movie-lab/`과 `/movie-lab-actions/`라는 경로가 포함됩니다.

Vite의 `base`는 배포할 때 사용하는 기준 경로입니다. 저장소 이름이 포함된 GitHub Pages 주소에서는 이 경로에 맞춰 설정해야 합니다.

예를 들어 `https://dbwn05-a11y.github.io/movie-lab-actions/`에 배포하는 경우, 공식 안내에 따른 `base` 값은 `/movie-lab-actions/`입니다.

자동 배포를 설정하는 것과 배포 주소에 맞는 경로를 설정하는 것은 각각 확인해야 할 작업입니다.

## 확인한 결과

실습 당시 두 배포 사이트에서 영화 포스터와 제목, `Inception` 검색 결과가 표시되는 것을 확인했습니다.

실습에 사용한 예제는 영화 검색을 위해 TMDB API 키를 입력하는 방식입니다. 이 글의 검색 결과 확인 내용은 실습 당시의 기록입니다.

## 배운 점과 다음 단계

빌드는 공개할 파일을 만드는 과정이고, 배포는 그 결과물을 사이트에서 이용할 수 있게 반영하는 과정이라는 차이를 배웠습니다.

자동 배포에서도 커밋과 푸시만으로 확인을 끝내지 않고, Actions 실행 결과와 공개 사이트의 화면을 함께 확인해야 합니다.

다음에는 자동 배포 설정 파일의 각 단계가 어떤 역할을 하는지 소스 코드와 함께 정리할 계획입니다.
